Previewing NBT and SNBT in Body Text ​

Create repair.md and stand.snbt side by side in assets/workshop/ageratum/en_us/maintenance/. The page only needs to reference the file in the same directory.

markdown
# Display Stand Base

<structure id="stand.snbt"/>

stand.snbt can start as a complete single-block structure.

text
{
  DataVersion: 3955,
  size: [1, 1, 1],
  palette: [{Name: "minecraft:anvil"}],
  blocks: [{pos: [0, 0, 0], state: 0}],
  entities: []
}
FieldTypePurpose
Tag attributes id, pathPath stringAt least one is required; id takes precedence. Relative paths resolve from the current Markdown file's directory.
sizeList of three integersStructure dimensions along X, Y, Z; length is checked during export.
palette or palettesList of block states or list of palette listsAt least one palette is required. States use Name and an optional Properties string map.
blocksList of compoundsEach entry has a 3-integer pos and palette index state. Block entity data can be placed in nbt on that entry.
entitiesList of compoundsOptional. No entities in this example, so an empty list is written explicitly.
DataVersionIntegerRecords the structure's data version. Keeping the game-exported value is recommended.

When specifying a namespace, use the full resource manager path, such as workshop:ageratum/en_us/maintenance/stand.snbt. If the extension is omitted, it tries the raw path first, then .nbt and .snbt. The component detects compressed NBT by its gzip header; otherwise it tries text SNBT first and then the alternate decoder. The text size limit is 8 MiB. For documentation previews only, SNBT is convenient for version control and manual review. Preview reading & format conversion

When the client cannot find a direct resource, it also queries the mod classloader for built-in NBT and SNBT under data/<namespace>/structure/ and structures/. This fallback only checks the classpath; for standalone previews use assets, as world-enabled server data packs do not enter this client classloader. Path resolution
